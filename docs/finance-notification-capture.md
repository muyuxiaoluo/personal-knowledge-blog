# 交易通知采集与补全

财富目前优先采用[月度账单整理](monthly-finance-review.md)。通知采集保留为可选来源；导入账单时可人工确认与已有通知的关联，避免在本机重复统计。

## 使用

通知采集、餐食拍照、健康与手工记账统一在“个人工作台”APP 内。安装使用 `deploy-artifacts/android/personal-workbench-arm64.apk`，不再单独分发财富功能包；构建与覆盖安装说明见 [Android 个人工作台](android-companion.md)。

手机与电脑需同时更新到支持本功能的版本。手机“账户与私人同步设置 → 交易通知自动记录”开启采集，分别授权系统通知访问与补全提醒。默认关闭采集，默认开启新交易即时提示。关闭采集保留原有记录并取消晚间提醒。

支持来源为微信支付（微信系统通知中可识别的微信支付发送者）和招商银行 App（`cmb.pb`），金额按人民币记录，明确标注外币的通知暂跳过。只保存识别出的金额、来源、通知到达时间、交易类型与后续处理结果。普通聊天不采集，通知原文不落库、不上传；多金额且无法判断、失败交易、营销和余额查询通知会跳过。纯金额通知先作为“待确认类型”，不直接统计消费。

手机首页与电脑财富页提供“交易待补全”。补一句用途、选择类型与分类即可保存。充值、提现、本人账户转移选“账户转移”；退款选“退款到账”。已明确的消费且没有疑似关联时，以“通知待补全”计入待分类支出；不明交易和疑似关联待确认后统计。时间先采用通知到达时间。

不同来源、金额相同、相隔不超过三分钟且类型相容的通知作为疑似关联候选，必须由用户确认。关联只保留一笔消费；也可以明确选择“这是另一笔交易，分别入账”。同一来源的独立通知保留各自记录；通知身份、消息时间和内容共同产生事件指纹，重复回调或重连重放不会重新入账。已处理通知可以修改用途、恢复忽略或取消关联。

即时提醒提供“立即补全 / 稍后处理”，滑掉或稍后处理均保留记录。短时间多笔交易更新同一张提醒卡片。每天按手机当地时间 22:00 检查全部未处理记录（含往日遗漏），有记录才提醒，每天最多一次；22:00 后新记录可即时提示，未处理的留到下一次晚间汇总。使用原生非精确闹钟，省电时可能延迟；重启、系统时间/时区改变和应用更新会重新登记。应用内可看到通知访问、服务连接与提醒授权状态。

后台监听直接写入手机 SQLite，并由同一数据库事务中的私人日志触发器记录。采集与提醒不依赖 WebView 常开；强行停止应用、禁用通知访问或系统阻断通知时会中断。打开应用、回到前台、保存补全和手动操作时沿用现有端到端加密私人同步；本版没有独立的原生云端上传任务。私人同步未开启时只保存在本机。

## 数据与核对

- `finance_capture_events` 保存通知证据和处理状态；与原始通知、设备授权设置分开。
- 正式交易使用由通知 ID 确定的稳定 ID。补全与正式账目在同一事务保存；修改用途更新原账目，不再新增。分批接收同步数据时，统计按稳定 ID 去重。
- 待补全的明确消费由查询投影进入列表、日历与月度汇总，不创建需要跨设备重复推导的临时账目。
- 关联状态与证据沿用私人 v4 密文同步，不进入普通 v3 同步。旧客户端无法理解新记录，使用前需双端更新；同步服务仍处理原有密文信封，无需新增明文财务接口。
- 当前不从金额推算准确余额，不自动关联退款原单。正式账单与通知的自动核对仍需后续补充；导入账单前应确认范围，防止同一消费再次录入。

## 无提醒或没有新增记录时

在“账户与私人同步设置 → 交易通知自动记录”检查采集、即时提示、通知访问连接及补全提醒授权。允许通知访问后仍需开启应用内采集开关。

- 列表已新增而无顶部提醒：先点击“测试提醒”。测试不新增交易记录，使用与新交易相同的提醒通道。若通知栏有测试卡片而无顶部提示，进入“提醒显示设置”检查“新交易补全”的通知、声音、悬浮/横幅显示及勿扰模式。
- 列表也未新增：核对“最近收到微信/招行通知”“最近记入交易”“最近提交即时提醒”三个时间和最近处理结果。诊断只保存时间和固定状态，不保存通知标题、正文或聊天发送者，也不进入云同步。
- 新版安装后又收到系统通知，三个时间仍为“暂无”：先点击新版“测试提醒”，等待最多约 8 秒。它用本应用生成的随机测试标记检查系统是否把通知交给监听服务，不生成交易，也不改变微信/招行接收时间。若显示尚未确认收到，在“设置通知访问”中关闭再开启“交易通知自动记录”，返回后再次测试；若收发检查通过但来源时间仍无变化，检查系统通知访问是否排除了微信/招行或对应通知类型。测试只覆盖本应用通知的投递，无法证明系统也放行了其他应用。
- 来源应用通知已到达但没有识别结果时，需核对脱敏通知模板；普通聊天、重复回调、合并摘要、旧消息和不支持的金额格式均可能被跳过。不要通过放开所有聊天来源来填补缺失模板。
