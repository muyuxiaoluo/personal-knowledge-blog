# 餐食照片：当前实现与接通步骤

## 已实现的本机流程

- 安卓首页“记一餐”：调用系统相机，或从相册一次选择最多 12 张 JPG、PNG、WebP 照片。
- 优先读取 JPEG 的原始拍摄时间预选日期、时间与餐次；缺少 EXIF 时使用文件时间，并提示核对。日期、时间和餐次可修改。
- 保存压缩副本（最长边最高 960 像素、JPEG 数据地址不超过 90,000 字符）。原相册文件保持原样。以原文件 SHA-256 去重，同一原图再次选入不会重复保存。
- 桌面“健康 → 今天吃了什么 → 餐食照片”：导入、预览、编辑草稿、点击识别、确认追加、删除照片。确认与餐食写入在同一事务内；重复确认不重复追加，已存在的文字和用餐时间保留。
- 删除照片保留已确认的餐食文字。识别失败保留照片，可手工填写后确认。未保存的健康编辑会阻止照片确认，确认写入期间暂停表单编辑。
- 照片的私人同步日志、游标、回执和冲突与既有文字记录隔离，已完成两个内存 SQLite 资料库之间的加密页面接收验证。

## 同步与识别

用户已确认同步服务器归属并授权加密传输所选餐食照片；AI 仅点击识别时发送，不启用自动识别。

- 手机和电脑均在“账户与私人同步设置”配对，使用同一恢复码，再开启“同步餐食照片”。该开关包括之前在应用保存的照片和草稿，不扫描整本相册。
- 照片经设备内 AES-GCM 加密后发送到当前同步服务器。独立接口为 `POST /v4/private/photos/sync`，每页最多 16 条，避免超过请求大小限制。原有 v4 文字记录和 v3 同步保持独立。
- 应用关闭或断网时照片留在本机。手机保存后/返回首页、联网或重新打开时同步；电脑联网、回到窗口或记录变更时检查同步。电脑健康页定期刷新本机照片列表。
- 电脑点击“识别照片”后，才将该张压缩照片发送给 `https://api.deepseek.com/responses`。识别文字可以修改，确认后追加到对应餐次。
- 服务端已按用户授权部署，详情见 [部署记录](meal-photo-deployment-2026-10-26.md)。服务器已有私人配对信息，未替换密钥或自动重配。

相册“分享 → 潇落”属于后续增强，本次实现通过“记一餐 → 从相册选择”导入。
