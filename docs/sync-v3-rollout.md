# 同步 v3、附件库与备份上线说明

本次改造只在本地代码中完成，不会自动部署服务器、发布桌面端、推送 Git 或创建标签。生产升级应先备份服务器 `/data` 命名卷，并保留当前桌面端安装包。

## 上线顺序

1. 先部署包含 `/v3/health`、`/v3/auth/*`、`/v3/sync` 与 `/v3/blobs/:sha256` 的同步服务器。
2. 验证 `/v1/sync` 仍可登录和同步无附件文章，再验证 v3 登录、刷新令牌、幂等重试与 Blob 的 HEAD/PUT/GET。
3. 在两份隔离的 Tauri 应用数据目录中安装新版桌面端，完成离线编辑、冲突、附件按需下载和 `.mgbak` 恢复演练。
4. 小范围发布桌面端；观察服务器磁盘、同步错误、冲突数量和 v2 请求量后再扩大。

新版客户端会先探测 v3。探测不到时回退到 v2，并明确提示只有无附件文章可继续同步；含 `attachment://` 的文章不会通过 v2 上传，因此不会在旧设备上形成缺图笔记。服务器会把兼容的 v3 文章变更双写给 v2 客户端，含附件文章除外。

## 数据与安全边界

- 原图与展示图都以 SHA-256 内容寻址存入服务器同一 `/data` 卷；数据库只保存清单与用户访问关系。
- 服务启动时及每 6 小时执行后台维护：只压缩 90 天前已被更新取代的 v3 历史，并清理超过保留期、已不再被任何附件清单引用的 Blob。刚上传但尚未进入清单的文件保留 24 小时，文件系统删除失败会留待下次重试。
- Access Token 默认 15 分钟；Refresh Token 最长 30 天、每次刷新轮换，服务端只保存哈希。改密码和注销会撤销相应会话。
- Windows 客户端把 Refresh Token 保存到凭据管理器，不写入 SQLite、日志或同步负载。
- v3 仍是用户自有服务器上的传输加密与访问控制方案，不是端到端加密。

## 备份与恢复

新版备份是单一 `.mgbak` 文件，包含 SQLite 一致性快照、附件原图、展示图和逐文件哈希。生成时先写临时文件，完整校验后才原子启用。

恢复会拒绝路径穿越、未声明文件、哈希错误、损坏 SQLite 和不兼容版本。替换现有资料前会自动创建 `mind-garden-before-restore-*.mgbak`；切换失败会恢复原数据库、WAL、SHM 与附件目录。旧 `.sqlite3` 仍可恢复，但不包含附件。

## 回滚

1. 暂停新桌面端分发，不删除服务器 v3 表或 Blob 文件。
2. 回滚同步服务器容器到上一版本，并继续挂载原 `/data` 卷；v1 数据仍然可用。
3. 客户端可退回旧版本，但旧客户端看不到只存在于 v3 的工作台实体和含附件文章。需要完整回退时，使用升级前 `.mgbak` 恢复新版客户端数据，再导出旧版可读内容。
4. 确认不再需要回滚且 v2 活跃客户端归零后，才可另行安排 v2 停用。后台 Blob 维护只处理超过 90 天保留期且已无引用的数据，不参与 v2 兼容切换。

## 发布前验收

- 桌面端 TypeScript 检查、单元测试、生产构建和 Rust 测试全部通过。
- 同步服务器测试通过，重点覆盖 v3 版本冲突、稳定 `changeId` 重试、分页、令牌轮换与 Blob 隔离。
- 使用真实 Tauri 应用完成大图粘贴、旧 Base64 迁移、离线重启、双目录同步、冲突三种处理、原图按需下载、备份恢复和主窗口/抖音/AI 内存回归。
- 逐页检查首页、行动、项目、笔记、AI、工具和设置，确认懒加载与 CSS 分层没有视觉回归。
