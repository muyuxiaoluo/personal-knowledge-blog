# 工作观察试用

从“启动开发调试”打开桌面应用，进入左侧“工作记录”。功能默认不自动采集，启动后也不会恢复上次的采集开关。

## 试用方式

1. 可选关联一个行动，并选择实际工作的文件夹（最多 3 个）。
2. 保留“整屏截图”和“本地 AI”，模型默认 `qwen3.5:4b-q4_K_M`。需安装 Ollama 并提前下载模型。Windows 下分析前会检查 `127.0.0.1:11434`；服务未运行时，工作台会按需隐藏启动 `ollama serve`，无需打开 Ollama 窗口。支持默认安装位置或 PATH 中的 `ollama.exe`，只读沿用 Ollama 桌面应用设置的模型目录（包括其他磁盘），未配置时使用原有环境变量与默认目录，不自动安装或下载模型。已运行的服务直接复用；退出工作台只停止由工作台启动的服务，留在托盘时服务继续运行。模型分析仍使用 `keep_alive: 2m`，空闲后模型可卸载。
3. 点“观察一次（3 秒后）”，可以切回编辑器或其他工作窗口。第一次文件扫描建立基线，不把已有文件算成新增。
4. 修改并保存一份文件，再观察一次，核对“文件变化”的前后片段和原图。
5. 需要持续记录时开启自动观察，建议每 5 分钟。应用留在托盘时后台采集继续；暂停或退出后停止。整屏截图包含桌面上其他窗口的可见内容。

## 记录内容与边界

- 前台窗口标题、应用名、采样时间、整屏原图。
- 指定目录内的文件新增、修改、删除；文本变化可展示前后片段。Markdown、LaTeX、代码、日志等支持 UTF-8 正文，单文件最多读取 128 KB；Word、PDF、图片等暂时只记录文件变化。
- AI 草稿有证据来源。它只能整理采样时的线索，不能确认整个任务完成、所有错误修复或判断工作的质量。不会自动更新行动状态、计划和“下一步”。
- 第二版将聊天/网页/编辑器等画面内容与程序确认的磁盘文件变化分开显示。文件内容整理必须逐字引用本次保存后的摘录，聊天与旧摘录不能充当本次文件改动依据。逐字引用校验仍不保证 AI 对原文的解释完全正确。
- “接续位置”独立显示最后窗口、可核对的文件名与原文引用，以及文件原文中的未完事项线索。文件名从采集证据取得，不采用模型生成的位置描述。未完事项由程序从保存后的片段提取，即使关闭 AI 或模型失败也保留；这不是任务完成或运行结果验证。默认仅识别部分明确的未完措辞与 TODO/FIXME，不保证覆盖所有表达。
- 同一采集会话、同一关联行动的 30 分钟内原始记录用于接续：保留最近窗口及最近文件变化，最多 2 次采样。连续采到聊天画面时不会立刻挤掉文件线索。不传递之前的 AI 猜测，也不发送历史图片。切换关联行动、采集文件夹或会话后不跨范围接续；近期采样不保证属于同一项工作。新文件改动会取代该文件的旧原文，不继续沿用已被取代的待办。
- 本次最多 6 份文件变化进入 AI，优先当前窗口标题提到的文件与有保存后正文的文件。文件摘录共同限制为 1200 字符，近期文件摘录最多 600 字符，界面标明未进入分析、摘录截断、无可引用正文以及近期采样数量。未进入模型的已采集文件变化仍可在记录里核对。
- 采集证据先落盘，AI 分析随后进行。模型未启动、不支持视觉、超时、输出截断或引用无效时保留原始记录，并显示具体原因。
- 自动观察在锁屏、连续 3 分钟无操作时跳过；画面与文件均无变化时不重复保存。工作台自身的画面不会自动再次截图，仍可追踪文件变化。间隔中发生但未被采到的事情无法补回；间隔内多次保存只体现最终差异。
- 片段按采集会话分组，关联行动变更、重新开启观察或 30 分钟没有新记录时分段；这不是准确工作时长，也不表示收工。

## 本地数据

数据在应用本地数据目录的 `work-observer/records.json` 与 `screenshots/` 中。最多保存 200 条观察，原图保留 7 天、总量上限 250 MB；清理在保存新记录时执行。试用数据不参与现有云同步、数据库备份与手机同步。开发版与正式版的保存位置不同。

文件扫描跳过名称以点开头的文件、常见构建目录、数据库、名称含 secret/credential/password 的文件与常见密钥扩展名，不跟随链接或 Windows 联接目录。其他正文可能含私人内容，因此只选择实际工作范围。扫描限制为 1500 个文件、8 层目录、3 秒和共 8 MB 文本；遇到扫描不完整时，不据此报告文件删除。

当前没有云端 API 调用、定时日报、睡眠和手机消费采集，也没有准确的工作时长统计。本地识别的效果需要按实际工作画面继续验证。

## 开发版实测（2026-10-03）

通过项目根目录“启动开发调试”运行真实 Tauri 应用，只修改独立示例文件夹。已验证整屏 2560×1600 原图保存、文件新增/修改及前后片段显示、本地 Ollama 分析、离开记录页面后的后台定时采集、工作台自身画面跳过、暂停与重启默认关闭，以及原图预览。原图支持按原尺寸滚动查看。

本机 `qwen3.5:4b-q4_K_M` 的几个整屏分析样本耗时约 9–15.5 秒。首次试验发现 4096 上下文不足，已使用 8192 并限制文件摘录；超大桌面仍可能超出模型能力，原始证据会保留。第一轮模型能提取“引用尚未校对”“实验尚未运行”等文字，但也出现把聊天里的描述当作实际操作、对已保存文件提出多余疑问、未生成接续线索的情况。

第二轮在同一开发入口验证了按来源整理：ChatGPT 画面被标为聊天内容，没有进入本次文件改动整理；前一次 `methods.md` 中的未完事项仍作为较早文件原文保留。9 份文件变化全部采集，6 份进入分析、3 份未进入的覆盖提示与实际输入一致。另一次示例将“引用尚未校对”改成“引用已校对；实验尚未运行，尚未编译验证”，界面显示新原文，不沿用旧的引用待办。随后连续 3 次无文件改动的手动采样仍保留了这份文件的原文线索。含文件改动的分析样本约 1.7–3.2 秒，整屏样本约 11.7–13.6 秒；这些是少量样本，不是性能承诺。

相关前端测试 13 项、原生采集与分析测试 15 项通过，桌面构建与类型检查通过。测试覆盖聊天/旧摘录/伪造引用不能作为本次文件依据、连续无文件改动采样保留近期文件线索、后续修改或删除取代旧待办，以及采集范围和会话隔离。模型仍可能给出多余疑问、漏选接续原文，或把同一文件的其他句子配作引用；逐字引用检查不能验证语义推断。界面保留文件原文供核对，当前仍适合试用自动留痕，不能把 AI 草稿当作可靠的任务完成判断。

锁屏与长时间空闲的判断已实现，本轮没有通过实际锁屏或等待 3 分钟验证。Word/PDF 正文读取、长期资源占用与真实工作场景的识别质量仍待后续验证。测试结束时自动观察保持暂停，示例目录从采集范围移除；示例记录保留在开发版中供核对。
