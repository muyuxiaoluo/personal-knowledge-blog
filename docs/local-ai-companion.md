# 浅羽桌宠

## 工作辅助和随手记

- 首页优先提供「开始投入 / 结束投入」「记一下」「委托」，委托页可以新建 Bug 委托和查看结果。「今日回顾」「资讯」「语音」「设置」放在次级入口。

- 拖动浅羽可以移动她，点她会在身旁展开气泡。空闲时原地思考、眨眼、伸懒腰或跳一小段舞，「设置」中可关闭自然待机。图集动作采用统一比例、脚底对齐的 60 帧/秒姿态，由同一个绘制时钟控制，解码完成后才开始，上一动作复位后再切换。绘制随屏幕节奏混合相邻姿态；待机使用固定站姿，呼吸、头部跟随和发梢由分区网格连续驱动，脚底固定。小舞步直接使用原站姿连续驱动左右点步、身体轻摆、手臂和裙摆，不切换头身比例不同的画像。关闭自然待机或系统要求减少动画时停止循环绘制，显示静态站姿。鼠标移开后头部柔和回正，摸头会浮出小爱心。停留不动 4 秒后人物淡出一些，移动后恢复，周围透明区域让鼠标通过。点「记一下」打开便签，正文和附加链接统一保存为待分类笔记。
- 右键点浅羽可以轮换抱兔、鼓劲、犯困、思考和小舞步；摸头会得到开心的小回应。抱兔、鼓劲、犯困三套 GPT 网页原生 GIF 各有 24 个原始画面；运行时使用 `desktop/asaba-motion/` 中的分块纹理，按需提前解码并释放旧页。旧转身 GIF 因头身比例变化已停用，内部 `spin` 标识现在对应 4.2 秒的原地小舞步。源 GIF 和提示词保存在 `sites-app/assets/asaba/emotions/`。实测和限制见 [动画流畅度记录](./asaba-animation-smoothness-2026-11-10.md)。
- 「心情小气泡」使用本地预设台词，最多每两分钟自动出现一次，约 6.5 秒后消失，不自动发声，也不调用模型。投入计时、朗读、听写、操作卡片及已知的空闲时段暂停自动闲聊。上下文反应沿用已授权的应用观察，不新增截图或应用授权；台词不会声称看懂页面、游戏结果或未读取的工作内容。小气泡位于人物头边，不抢焦点，其区域可点击穿透。设置中可单独关闭文字气泡，右键动作仍可使用。
- 「语音」或 Ctrl + Alt + Space 启动本机 Sherpa-ONNX 中文流式听写，逐段显示预览；「停止并放入笔记」或 Esc 结束收音并保留正文，「继续听写」另起一段。单次最长两分钟，平时不开麦。运行 `sites-app/scripts/install-asaba-asr.ps1` 安装独立环境和官方中文模型，配置保存在 `%LOCALAPPDATA%/PersonalWorkbench/asr/runtime.json`；模型在 CPU 上运行，不保存或上传音频。
- 「记一下」统一保存为待分类笔记，网页链接作为正文附件；项目、链接和画面选项收在「＋附加」。保存成功后显示去向，可查看笔记、继续记录或从该笔记整理委托；委托页也能从已有浅羽笔记选择内容。
- 朗读使用 `D:\AI voice\Qianyu-TTS` 的 V5 Turbo 音色。正文逐句合成，每句最多 28 字，播放当前句时仅预先生成下一句。模型空闲释放后，首次朗读会先加载音色，界面显示加载、等待或合成状态；加载可能需要几分钟，后续短句复用已加载模型。朗读可以暂停或停止，出错后可从当前句重试。音色服务离线时，通过本机控制入口或直接启动已安装的 Python 服务加载音色。
- 在「设置」开启桌面观察后，浅羽会对浏览器、编辑器和已授权的游戏作出短暂的表情反应。普通应用只记名称和前台时段。游戏按程序授权，浏览器仅授权本次窗口，换标签页仍在范围内，关窗失效。获准的前台窗口每 20 秒检查画面变化，同窗口留图至少间隔 90 秒，每天最多 30 张，保留 7 天。
- 「今日回顾」和「资讯」默认阅读文字，需要时点「朗读」。回顾保存在本机，收起气泡或重启后复用当天结果，显示整理时间，点「更新回顾」才重新整理；整理中可取消，也可继续使用记笔记和委托。收起气泡自动暂停朗读，再次打开可从原进度继续或停止。「资讯」显示当日缓存的每日早报全文，AI 资讯仅显示和朗读命中工作台关注词的标题。

## 投入计时

- 气泡中可以直接开始和结束投入，支持临时起名、可选关联项目，也可以搜索已有行动。记录写入工作台现有投入历史。
- 开启桌面观察和投入提醒后，在编辑器或文档应用持续使用 10 分钟会出现提示，点击确认后开始计时。连续 5 分钟没有键鼠操作时提醒确认结束，计时继续保留。锁屏期间不会自动创建投入，应用重启后的未结束记录沿用工作台恢复流程。

## 项目委托

- 项目可在「动态 → 项目目录」绑定本机 Git 仓库。从笔记创建委托时会带入绑定目录。可用浅羽的本机模型整理说明并编辑确认，原笔记保留。
- 每条新委托创建新会话，点已有委托的「继续处理」会接续同一条 Bug。提交前可选择独立 Git 副本或项目原目录，界面会提示未提交改动。原目录结果显示相对执行前基础提交的目录差异，包含已有改动。项目动态保留结果和执行会话入口。
- Codex 是当前的执行工具。Windows 上执行需要支持 MXC 隔离的 Codex 和系统版本，工作台会核对执行目录的权限。参见 [Codex 的 Windows 隔离说明](https://learn.chatgpt.com/docs/windows/windows-sandbox)。
- 观察数据、窗口截图和委托副本位于应用数据目录的 companion/asaba。既有 Codex 摘录仍在 companion/records.json。桌宠回顾和随手记无需安装 DeepSeek Harness。

## 后续常开与云端方案（暂记，不实施）

先根据本机使用确定需要持续运行的具体任务、内存占用、模型调用量和存储量，再选择部署方式。模型在本机还是通过 API 调用，与程序部署在哪里分别决定。

| 选择 | 更适合的情况 | 需要承担的工作与限制 |
| --- | --- | --- |
| 自购小主机，家中常开 | 主要读取本机文件和应用，重视本地数据，希望手机离桌后仍可访问 | 电力、网络、远程连接、备份、更新；电脑应用通常仍需要可用的桌面会话。大模型硬件需求另计。 |
| 租云服务器 | 定时检查公开信息、运行联网服务和批量任务，希望不依赖家庭网络 | 持续租金、服务维护、凭据与网络管理；访问家中 Codex 和文件仍需本机连接程序。普通 Linux 服务器不直接代替 Windows 桌面应用。 |
| 直接使用 Muse / Grok Bot 等成品 | 需求以它们支持的应用、云端浏览器和现成功能为主，优先减少维护 | 订阅与服务条款、连接器覆盖、资料迁移和可定制程度；对本机应用的覆盖要逐项验证。 |
| 混合使用 | 本机收集与个人资料留在自己设备，少量持续联网任务交给外部服务 | 需要明确两边的数据范围、任务归属和同步方式，避免重复执行。 |

目前保留前三种选择和混合方式，不预先推荐购买。条件明确后再核对当时的服务能力、价格和设备需求。

参考：[Muse](https://muse.ai/)、[Grok Bot](https://docs.x.ai/grok-bot/get-started)、[DeepSeek Harness](https://deepseek.com/harness/)、[Codex App Server](https://learn.chatgpt.com/docs/app-server)。
