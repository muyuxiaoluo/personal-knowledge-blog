# 月度账单整理

财富以每月导入微信账单为主要入口，继续支持支付宝账单；银行等少量支出在月末手工补记。本轮不新增银行账单接入。

## 使用

1. 从微信官方应用申请上月的个人对账明细，下载并自行解压，在财富页选择“导入月度账单”。文件只在本机解析。
2. 预览包含已有通知的相似候选：相同金额、类型相容、相隔不超过十分钟。逐项勾选确认是同一笔交易；金额和时间相近本身不会自动合并。微信通知只匹配微信账单，招行扣款通知可以作为绑卡付款的候选。
3. 导入后进入对应月份的“月度整理”。相似商家和用途集中确认，明细可以排除个别交易。也可以暂留待分类。
4. “记住这类分类”会用于后续导入。无需选择消费性质；关联项目和是否值得均保留为可选项。美团、滴滴等多用途平台会同时匹配商品说明，避免把不同服务一律归为同类。
5. 地铁、公交、打车、骑行有独立分类，原有交通预算包含这些细类。银行卡 / 其他支出可直接补记；回顾往月时，补记日期默认该月最后一天。

原有通知记录折叠为可选入口。手机上的采集与即时提醒仍由用户的原有开关控制，月度整理不依赖这些提醒。

## 数据约定

- 同来源流水号和文件指纹继续用于重复导入检查；缺少流水号且内容相似的记录留给用户确认。
- 通知与账单的人工关联仅存本机。统计采用正式账单，原通知和已补全账目保留，已作出的分类、消费性质、项目和评价会带入账单。关联退款在本机统计中指向正式账单。
- 撤销整批导入同时撤销该批关联，恢复原通知的统计。已有其他记录直接关联该批付款的退款时，先解除退款关联再撤销，避免留下失去原付款的退款。原通知内容和私人同步记录不会因本机关联而改写；手机上仍保留通知记录。导入账单和分类规则沿用本机保存范围。
- “待分类”只按分类确认状态判断，未填写消费性质不会要求逐笔处理。消费性质仍以未知参与相关分析，不自动推断其必要性或节省金额。
- 新增出行细类属于客户端共享分类枚举；需要同步含新细类的手工/通知记录时，两端应使用支持这些细类的版本。月度导入账单本身不进入私人同步。

## 账单接口核查

2026-11-06 核查公开文档：微信支付的申请交易账单 API 面向商户，未找到向第三方开放个人全部消费流水的公开接口。个人流水仍从微信内申请下载。当前没有自动登录微信、读取邮箱或定期拉取账单。

- [微信支付商户账单接口](https://pay.wechatpay.cn/doc/v3/merchant/4013421450)
