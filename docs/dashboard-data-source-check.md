# AI 动态与日报数据源排障

## 2026-11-11 故障与修复

- 旧域名 `aihot.virxact.com` 返回 301，迁移到 `aihot.news`；原请求禁止跳转，刷新直接失败。
- 日报的 `lead` 返回 `{ title, leadParagraph }`，分节条目没有精选动态所需的 `id`。原解析失败后被忽略，因此日报入口消失。
- 已切换新域名、允许最多 5 次跳转，兼容实际日报结构，并保留旧域名链接的识别能力。
- 主接口失败时保留缓存，卡片持续显示失败原因与最后成功时间；专题或日报单独失败时保留可用动态并显示具体接口错误。成功后清除提示。
- 手动刷新、旧域名缓存、带部分失败提示的缓存会完整拉取，避免 304 阻止日报恢复。

## 发现与定位

应用首页可见时，每分钟检查缓存是否过期，AI 动态缓存有效期为 30 分钟。到期刷新失败会直接显示在卡片和阅读窗口，手动刷新也会提示结果。应用关闭期间不会巡检。

在 `sites-app` 运行 `npm run check:aihot`，会调用与应用相同的后端请求与解析代码，检查精选动态、专题和日报；任一请求或解析失败都会以非零状态退出，输出具体接口错误。此检查读取公开数据，不修改业务数据库。普通 `cargo test` 不依赖外网。

本地回归覆盖：301 跳转、跳转上限、ETag / 304、日报两种导语结构、摘要条目缺少动态 ID，以及部分接口失败时保留资讯并返回诊断。

## 后续持续发现方案

如需应用关闭时也能发现故障，可在持续集成中每小时运行真实接口检查，连续两次失败再通知维护者，恢复后发送一次恢复通知。检查必须同时验证请求、数据解析和内容日期，避免只检测 HTTP 200；内容超过约定更新周期应单独提示陈旧。

遇到告警先按错误区分：301/308 查看跳转目标并核实新域名；解析失败对比响应结构；429/5xx 按服务端重试要求恢复；内容陈旧检查源站是否停更。修复后先跑对应回归和真实接口检查，再在 Tauri 应用中手动刷新确认，最后发布版本。
