首次应用内联调反馈：用户在验证码之后遇到错误；只读检查确认尚未发起数据同步，故失败仍在登录收尾阶段。已将原手工合并 Cookie 改为遵守域名、路径的标准会话存储，对齐成功验证工具的完整验证请求标识及请求专用设备 Cookie，并保留验证码响应中的 HTTP Location 跳转。错误提示增加失败步骤和纯数字错误码，并保存到本机同步设置供定位；不会保存密码、验证码、Cookie、原始响应或带登录参数的地址。新增回归覆盖会话作用域、临时设备标识、验证码 JSON/HTTP 跳转及错误脱敏。真实账号需在修复后的入口重新登录确认。

后续反馈为“验证码之后未取得小米登录状态（错误码 70016）”。对照 [go2rtc 的小米登录实现](https://github.com/AlexxIT/go2rtc/blob/master/pkg/xiaomi/cloud.go) 发现另一条登录收尾路径：验证码跳转链的 `Extension-Pragma` 响应头可提供 `ssecurity`，其他登录字段分布在多次跳转的 Cookie 中。原程序只保留健康令牌，遗漏了这些登录字段，随后额外的无凭据 `serviceLogin` 查询可能以 70016 结束。现已逐跳收集登录结果；结果完整时直接结束登录，只有通行令牌时显式兑换服务登录状态。继续使用原检查路径时，错误会指出缺失字段名称，不包含字段值。新增离线回归通过禁止网络请求验证：完整跳转结果不会再触发额外登录检查，并覆盖跨跳转字段保留及新旧会话密钥隔离。该遗漏与实际反馈相符，真实账号仍需在新版本完成一次确认。

再次联调反馈“登录已过期”，但本机同步设置尚无尝试时间，证明错误仍来自首次登录而非验证码计时或数据同步。发现首次收尾曾调用新建会话的续期函数，丢失刚验证过的身份会话上下文；已改为在同一会话中携带刚收到的账号/通行令牌完成服务登录。服务 Cookie 也允许从已限制范围内的小米账号回调接收，不再仅依据请求主机名识别；固定占位标记仍排除。新增离线回放验证首次服务请求确实保留身份 Cookie，并区分首次服务登录失败与后台续期被拒绝，错误不含凭据值。

本次联调明确缺少的是 `ssecurity`，其他四项登录字段已经取得。参考 [Xiaomi-Update-Info 的登录源码](https://github.com/YuKongA/Xiaomi-Update-Info/blob/main/XiaomiUpdateInfo.py)，其身份验证成功后会再次提交本次账号认证。现为首次登录增加对应分支：同一会话的服务查询返回 70016 时，用该查询的新认证参数及本次内存中的密码摘要再认证一次，然后完成服务跳转；拒绝后即停止，不循环提交。摘要随待验证状态保留在内存，未写入数据库或系统凭据。成功 JSON 响应中的登录字段也会在跟随跳转前保留。

为了让后续失败可以直接定位，登录错误会在本机同步设置中同时保存最多 40 条诊断记录。字段限于固定步骤名、请求方法、HTTP 状态、数字错误码及字段是否存在的布尔值；不保存账号、验证码、密码摘要、Cookie、密钥值、原始响应或登录地址。离线回放覆盖 70016 后同会话认证、使用新的认证参数、服务跳转、拒绝后停止、响应字段保留和诊断脱敏。此项对真实账号的适用性仍待本轮登录确认，离线通过不代表真实登录已经通过。

## 财富先准备两类实际样本

1. 微信：进入“我 → 服务 → 钱包 → 账单”，在常见问题或相关菜单中找“下载账单”，选择个人对账，申请最近一个月账单。按微信提示收取邮件并在本机解压。现有工作台“财富 → 导入微信账单”支持 CSV/XLS/XLSX。
2. 招行储蓄卡：在招商银行 App 搜索“流水打印”或“交易流水”，申请同一月份并发送本人邮箱。实际可导出格式以 App 为准；目前工作台尚不支持招行流水解析。
3. 将样本保存在本机 `deploy-artifacts/data-automation-samples/`。该目录被 Git 忽略。后续在本机检查文件格式，无需上传到聊天或代码仓库。

这些导出申请可能需要支付密码、短信或人脸验证，相关步骤由本人在官方 App 内完成。

## 再验证手机通知覆盖率

支付通知采集尚未实现。开发时在现有 Android 伴侣加入经本人授权的通知诊断入口，只提取支付类通知中的必要字段。安装候选 APK 并开启通知访问后，用日常发生的微信付款、招行直接付款和退款核对通知是否包含金额、商户和时间；无需为了验证另做交易。

安卓通知监听能收到的系统通知，不一定涵盖微信应用内的所有支付消息。先验证真实覆盖情况，再决定正式自动采集范围。日常采集记录先标为待核对，官方账单用于定期补齐、修正与确认。

微信绑定招行卡的同一笔消费只能统计一次。银行扣款与微信消费应关联；微信零钱充值、提现及本人账户间转账按账户转移处理。现有同来源去重规则需要扩展，无法可靠关联的记录进入待确认列表。

账户余额及净资产另需余额基准和资产记录，仅有消费通知不足以保证余额准确。第一阶段优先处理交易采集和核对。
