# 小米健康七天读取验证

本工具验证本人小米运动健康账号的云端步数和睡眠是否可读取。`run.cmd` 用于只读核对，`connect-desktop.cmd` 用于把登录状态安全交给当前工作台。两者都不直接改写健康数据库。

## 当前工作台连接入口

当前健康页点击“连接小米账号”显示小米登录二维码，用手机“扫一扫”并确认登录。此入口由原生部分实现，不依赖终端或 Python。手机确认后的真实账号连接及首次同步仍在联调。

本目录保留此前的终端排查工具，供定位密码/验证码登录使用。`connect-desktop.cmd` 复用 `run.cmd` 的认证函数，确认健康服务可读取后，将完整登录状态保存到工作台的 Windows 凭据位置。当前此密码/验证码路径也出现 70016，尚未解决，不作为健康页的默认连接方式。

密码、验证码及密码摘要均不保存；保存的是接口返回的服务密钥、服务令牌及续期登录状态。交接只使用系统凭据管理器，不启动监听服务、不写凭据文件、不把凭据放入命令参数或环境变量。断开连接沿用应用已有的删除凭据功能。

## 怎么操作

1. 手机打开小米运动健康，确认使用的账号，并在应用内完成云同步。如果找不到同步开关，先打开首页刷新，具体入口以手机版本为准。
2. 在本文件夹双击 `run.cmd`。当前电脑所需运行环境和依赖已经准备好。
3. 在弹出的窗口输入同一个小米账号和密码。密码输入时不显示字符，输入完按回车即可。出现图片、短信或邮箱验证码时，在本机窗口按提示完成验证。
4. 等待生成并打开“七天核对”报告。先选其中一天，对照手机里的步数、入睡和起床时间，再核对其余日期。睡眠按起床日期归档。

请只反馈“登录是否成功、是否读到步数/睡眠、与手机是否一致”以及错误提示。密码、验证码和登录凭据留在本机输入。

报告位于 `.local/results/时间/`。`raw.json` 是接口健康记录，`summary.json` 是整理结果，`report.html` 供本机查看。若新版本手机的数据格式尚未识别，原始文件可供后续在本机检查。整个 `.local/` 已加入 Git 忽略规则。

## 结果怎么判断

- 时间范围为北京时间最近七个完整日期，排除今天。为保留跨夜睡眠，睡眠查询额外覆盖前一日。
- 步数按来源分列，分页重叠在同一来源内去重。多来源的合并规则须与真实手机数据对照后确定。
- 没有记录显示为“未返回记录”，不会记成 0。
- 睡眠显示起止时间、起止间隔与小米报告时长。本次手机数据已确认 `duration` 单位为分钟，整理结果使用 `reportedDurationMinutes`。起止间隔可能包含清醒时间，两者分别保留；缺少接口时长时不推算。新数据源的单位仍需核对。
- 接口错误、未知字段、分页停滞会明确失败，不当作成功同步。
- 没有返回睡眠时，先核实手机云同步。应用内已有记录仍可能尚未上传，或当前云端接口不包含该类型，需进一步定位。

## 本机数据与依赖

只读核对模式下，账号密码、验证码、登录 Cookie 和令牌仅用于当前进程，不写入配置、日志或报告；没有调用上游保存会话的方法。连接工作台模式仅将完整登录状态交给系统凭据管理器。报告只保存步数和睡眠健康数据。请求仅允许 HTTPS 的 `account.xiaomi.com`、`sts-hlth.io.mi.com`、`hlth.io.mi.com`；不启动任何网络监听服务。

复用 [Aaron-gx/mihealth-api](https://github.com/Aaron-gx/mihealth-api) 的登录及协议实现，固定提交 `05edd1308025795e124f8958b20f8408c41b1c82`，MIT 许可证位于 `.local/vendor/LICENSE`。`upstream.json` 记录文件 SHA-256，启动时逐个核验。上游属于非公开接口实现，真实账号可用性与后续接口变化仍需实测。

`run.ps1` 优先使用本机 Codex 附带的 Python，缺少时使用系统 Python 3.10+。新电脑首次执行会下载固定上游文件，并将 requests 依赖安装到 `.local/runtime/`。不会自动登录；交互式账号登录由使用者本人完成。

开发检查：`run.ps1 -CheckOnly` 只校验环境，不登录、不读取健康数据；`python -m unittest discover -s tools/xiaomi-health-check -p test_verify.py` 运行离线样例测试。
